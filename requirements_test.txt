# Test dependencies for LOCAL use.
#
# pytest-homeassistant, Home Assistant's own test plugin, pulls in the Home
# Assistant release of the same version plus the fixtures for custom
# integrations. It replaced pytest-homeassistant-custom-component, which
# ended with Home Assistant 2026.10. The two cannot be installed together:
# in an environment that still has the old one, uninstall it first.
#
# Deliberately UNPINNED here: locally you want whatever is current, and only a
# current Home Assistant surfaces deprecations and API removals - an old pin
# makes the integration look healthy while it is already broken. (Verified:
# pinning to 0.13.205 / HA 2025.1.4 hid the removal of the OptionsFlow
# `_config_entry` compatibility shim, which only showed up against HA 2026.7.2.)
#
# The two TEST matrix jobs do NOT install this file. They install a plugin
# release by name, so the log says which Home Assistant ran, and the minimum
# job needs the older plugin. See .github/workflows/test.yaml and
# .github/scripts/resolve_ha_plugin.py.
#
# The mypy job does not install it either: it needs Home Assistant's own
# type information from the same plugin release the current test job
# runs, and installs that directly.
#
# The OPPOSITE mistake - using an API that does not exist yet on the declared
# minimum - is caught by the "minimum" job of the test workflow, which pins
# the plugin release matching hacs.json.
pytest-homeassistant
# Declared rather than inherited. The old plugin brought it along and the
# new one does not, and tests/test_e2e.py relies on it
# (`pytest.mark.timeout(120)`): a marker nothing registers is a silent no-op.
# The matrix jobs do not install this file at all, which is why they name it
# themselves.
pytest-timeout
-r requirements_runtime.txt
